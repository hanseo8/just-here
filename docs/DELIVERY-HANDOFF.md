# 배달 핸드오프 — 왜 배달앱을 거치지 않는가

## 문제

배달 모드가 사용자 문제를 풀지 못하고 있었다. 우리가 가게를 추천하고 나면
사용자는 배달앱을 열어 그 상호를 **다시 검색**해야 했다. 그 순간 배민은 이미
카테고리와 사진으로 "뭐 먹지"를 우리보다 잘 보여준다. 그냥여기를 거칠 이유가
사라진다.

게다가 추천 자체가 부실했다. 카카오 로컬 API는 배달 가능 여부를 주지 않는데
`kakao.py`가 `delivery_available = True`를 그냥 박아넣고 있었다. 배달을 안 하는
가게를 배달 모드에서 추천할 수 있었다는 뜻이다.

## 조사 — 배달앱 딥링크는 존재하지 않는다

| 앱 | 결과 |
|---|---|
| 배민 | `baemin://` 검색 경로가 공개된 게 없다. 커뮤니티에 도는 건 추측이고, 미지원이면 앱만 열린다 |
| 요기요 | 내부 API(`/api/v1/restaurants-geo/`)가 개발자도구로 노출돼 있으나 키를 뜯어 쓰는 비공식 엔드포인트다. 약관 위반이고 언제든 막힌다 |
| 쿠팡이츠 | 웹 주문은 되지만 로그인·주소 설정을 먼저 요구하고, 검색어를 URL로 넘기는 방법이 공개돼 있지 않다 |
| 땡겨요 | WebSquare SPA(`?w2xPath=...`)라서 딥링크가 내부 XML 경로에 묶인다. 로그인도 필요하다 |

즉 붙일 딥링크가 없다. 제휴를 뚫는 길밖에 없고, DAU가 아직 없는 상태로는
현실적이지 않다.

## 결정

배달앱을 **경유하지 않는다.** 자사 주문 페이지가 확인된 프랜차이즈만 추천하고,
그 주문 페이지로 바로 보낸다. 자사 주문 웹은 일반 공개 URL이라 딥링크 허가가
필요 없다.

이 결정이 얻는 것:

- **배달 가능 여부 문제가 사라진다.** 프랜차이즈는 전국 배달이 전제라 확인할 게 없다. 배달 덱은 카카오 API에 의존하지 않는다.
- **탭 한 번으로 주문 화면까지 간다.** 검색 단계가 없다.
- **데이터를 우리가 소유한다.** 외부 API가 죽어도 배달 모드는 산다.
- **위치 권한이 필요 없다.** 전국 배달이므로 좌표 없이 동작한다.

받아들이는 한계:

- **동네 맛집은 못 잡는다.** 프랜차이즈만이다. 동네 중국집을 원하면 배민으로 가야 한다.
- **주소 입력은 남는다.** 브랜드 주문 페이지에서 배달 주소는 넣어야 한다. 다만 이건 주문 절차이고, 우리가 없애려던 건 "결정을 다시 하는 것"이다.
- **브랜드가 URL을 바꾸면 깨진다.** 그래서 검증 스크립트를 둔다.

## 구조

```
intent=delivery → engine.build_brand_cards()  → brands.BRANDS
intent=visit    → engine.build_visit_cards()  → kakao/허브 재고
```

- `backend/app/brands.py` — 카탈로그. 브랜드당 대표 메뉴·분류·예산·주문 URL.
- `engine.build_cards()` — 모드로 덱 소스를 가른다.
- `engine.build_handoff()` — `order_url`이 있으면 `provider="brand_direct"`로 그 URL을 내려보낸다.
- `duo.py` — 듀오 배달도 같은 카탈로그를 쓴다.

배달 카드는 **거리·ETA·주소를 만들어 내지 않는다.** 브랜드는 지점이 아니므로
그 값들이 존재하지 않는다. 대신 예산(히어로), 분류, 주문 채널, 한 줄 이유를
보여준다.

## 브랜드 추가하기

1. 모바일 UA로 주문 URL을 열어 **200이 뜨고 실제 주문 화면이 나오는지** 확인한다.
2. 앱 설치나 로그인을 먼저 요구하면 **넣지 않는다.** "두 번 클릭 안 한다"는 약속이 깨진다.
3. `brands.BRANDS`에 항목을 추가한다. `category`는 기존 취향 어휘(korean·western·meat…), `kind`는 사용자에게 보여 줄 한글 분류(치킨·피자…)다.
4. 검증한다.

```bash
python scripts/check-brand-urls.py   # 주문 URL 전수 상태 확인
python scripts/check-brand-flow.py   # 배달/방문 덱과 핸드오프 계약 확인
```

제외한 브랜드와 이유: bhc(웹 주문 없음 — `/order` 404), 굽네·맘스터치·써브웨이(앱
또는 로그인 강제), 처갓집·멕시카나·신전떡볶이(정적 브로셔 사이트).

## 나중에

- 브랜드 제휴는 배민 제휴보다 뚫기 쉽고 어필리에이트 수익 경로가 열린다.
- 동네 가게는 `tel:` 포장·픽업 모드로 원클릭 완결이 가능하다. 배달과 방문 사이의 세 번째 모드 후보.
