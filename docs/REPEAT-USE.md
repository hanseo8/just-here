# 4번 최근 선택·취향 재사용

- 저장된 음식 취향이 있으면 홈에 '지난 취향으로 다시 찾기'가 나타난다. 현재 유효한 음식 키만 중복 제거해 최대 3개 재사용하고 방문·배달/거리 선택으로 이어진다. 일반 메뉴 고르기는 새로 선택하는 흐름을 유지한다. 위치 실패 시 기존 수동 선택 흐름을 따르며 임의 좌표를 사용하지 않는다.
- 저장값이 없거나 더 이상 유효한 음식 키가 없으면 재사용 버튼을 숨긴다. 저장된 취향을 선택 완료한 경우 기존 taste_done 이벤트에 source=saved_taste를 기록한다.
- MY에는 접힌 '최근 고른 가게'를 추가했다. 기존 swipe_logs의 lets_go만 읽어 최근 30일, 가게별 최신 1건, 최대 5곳을 보여준다. 같은 초의 기록은 나중에 저장한 선택을 우선한다. 실제 방문·결제 완료로 표시하지 않는다.
- 유효한 카카오 가게 ID가 있는 방문 선택만 고정된 카카오맵 링크로 연결한다. 외부 임의 URL·좌표·사진 참조를 새로 저장하지 않는다.
- 프로필 조회는 기존 본인 토큰 검증과 no-store를 유지하며 최근 선택을 별도 저장하지 않는다. 기존 프로필 삭제에 함께 제거되는 기존 로그를 사용한다. 지갑 접수 중지와 무관하게 최근 선택 조회를 시도한다.
- MY 칭호의 최상단 배치는 유지한다. 늦은 날씨 추천이 사용자가 이미 고른 방문/배달 방식을 바꾸지 않도록 보호한다.

검증: check-repeat-use.py(임시 사용자/본인 한정/삭제/재접속/중복·시간 필터), check-repeat-ui.cjs, 기존 위치·MY·유입 집계 회귀 및 계정 삭제 실행기 검사를 통과했다. 390px 모바일에서 재사용 후 방문·배달 단계 이동, 최근 선택 목록 및 빈 상태를 확인했다.
로컬 검수 화면의 가게·취향·위치·날씨는 검증용 데이터이며 실제 사용자 기록을 사용하지 않았다. 새 네이티브 앱 패키지 생성은 별도 작업이다.
