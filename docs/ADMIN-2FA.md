# 관리자 2단계 인증

## 구현 상태

인증 앱의 TOTP 6자리 번호 + 기존 X-Admin-Token을 사용한다. 인증 세션은 메모리에만 10분 유지하며 재시작 시 소멸한다. 사용한 인증번호의 시간 구간은 DATA_DIR/admin-security.sqlite3에 저장하여 재시작 후에도 재사용을 막는다. 실제 보존 여부는 DATA_DIR 영구 디스크에 달려 있다.

보상 관리자와 통계 화면에 선택적 인증번호 입력란을 제공한다. API 클라이언트는 POST /v1/admin/auth에 {"otp":"6자리 번호"}와 X-Admin-Token을 보내고, 응답의 session_token을 X-Admin-Session 헤더로 보낸다. POST /v1/admin/logout은 해당 세션을 폐기한다.

## 운영 활성화: 관리자가 직접 수행

프로젝트 폴더에서 **본인이 직접 개인 터미널**을 열고 다음을 실행한다. 화면 공유·터미널 기록 수집은 먼저 종료한다. 이 명령을 에이전트에게 실행시키지 않는다.

```powershell
python -B -m scripts.setup-admin-2fa --create
```

Google Authenticator 또는 사용하는 TOTP 인증 앱에서 계정을 추가하고, 도구가 표시한 키를 직접 입력한다. 시간 기반으로 등록한 뒤 도구에 6자리 번호를 입력한다. 번호가 맞아야 Render 설정 안내가 나온다. 도구는 네트워크에 연결하지 않고 파일·클립보드·Render를 변경하지 않는다. 터미널 화면에는 키가 표시되므로 채팅에 붙이지 않는다. 작업 후 터미널을 닫고 인증 앱을 유지한다. 실패·취소한 등록을 다시 시도할 때는 새 키가 생성되므로 앱의 이전 미완료 항목과 혼동하지 않는다.

현재 코드 추가만으로 활성화되지 않는다. 먼저 관리자 소유 인증 앱에 별도의 무작위 Base32 비밀키(32~128자, A-Z/2-7, 패딩 제외)를 등록한다. 기존 ADMIN_TOKEN이나 사용자 서명 키를 재사용하지 않는다. 비밀키는 채팅·저장소·스크린샷에 남기지 않는다.

등록한 키를 Render 서비스 Environment의 ADMIN_TOTP_SECRET에 넣는다. 키가 있으면 즉시 2단계 인증이 요구된다. ADMIN_REQUIRE_2FA=on을 함께 설정하면 키 누락 시에도 접근을 차단한다. 이 환경 설정 적용은 서버 재시작을 유발하므로 운영 백업 및 배포 확인 후 수행한다. 인증 앱 등록을 끝내기 전에 설정하지 않는다.

인증 앱 시간을 자동 동기화한다. 이전/현재/다음 30초 구간을 허용하며, 로그인한 번호는 다시 쓸 수 없다. 재로그인 시 새 번호를 기다린다. 세션은 서버 재시작 또는 ADMIN_TOKEN/ADMIN_TOTP_SECRET 변경으로 무효화된다. 비상 복구는 Render 계정 접근권한이 필요하다. Render/GitHub 계정에도 MFA를 설정한다.

## 보안 이벤트

GET /v1/admin/security는 인증된 관리자에게 차단 종류별 누적 횟수·최근 시각을 제공한다. 고정된 다섯 종류만 저장하며 토큰·번호·IP·본문은 저장하지 않는다. Render 로그는 종류당 분당 최대 한 번 기록한다. 외부 알림 발송은 구현하지 않았다.

관리자 로그인은 클라이언트당 분당 5회, 전체 분당 30회 제한한다. 기존 요청 제한과 함께 적용되며 단일 프로세스 제한이므로 분산 공격 방어 서비스와 동일하지 않다.

## 검증

python -B -m scripts.check-admin-security: RFC 6238 SHA1 공식 벡터, 설정 누락 시 차단, 보호 API 접근, 만료, 세션 초기화 후 OTP 재사용 거절, 비공개 집계를 검사한다. 실제 운영 인증 앱 등록 및 활성화 검증은 별도다.
