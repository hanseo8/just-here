# 보상 모집 전 보안 조건

2026-10-04: 기존 원장 트랜잭션·중복 지급 제한·계좌 암호화·관리자 토큰·보상 OFF 장치를 유지했다. 동일 목적의 별도 인증 또는 원장을 추가하지 않았다.

이번 보완:

- 공개 게스트 API에서 검증되지 않은 Firebase 사용자 ID를 거절한다. 기존 기기 연결과 서버 발급 UID는 유지한다.
- 잘못된 문자·과도한 길이·잘못된 서명·잘못된 만료 형식의 토큰은 예외 대신 인증 실패로 처리한다.
- 관리자 인증은 X-Admin-Token 헤더만 허용한다. 통계 UI는 URL 토큰과 브라우저 영구 저장을 사용하지 않는다.
- 통계의 취향·분류 등 외부 문자열을 HTML로 실행하지 않고 문자로 표시한다.
- 사용자·관리자 민감 응답은 no-store로 보내며 nosniff와 same-origin Referrer-Policy를 적용한다.

검증: `scripts.check-security`, `scripts/check-analytics-security.cjs`, 보상 API·지급 복구·기존 브랜드 흐름 회귀. 이 검사는 전체 침투 테스트나 외부 의존성 취약점 검사 완료를 의미하지 않는다.

모집 전에 남은 조건:

- 영수증 실제 디코딩·픽셀 제한 및 업로드 요청량 제한. 현재는 8MB·MIME·매직 바이트 검사이며 완전한 이미지 검증이 아니다.
- 관리자 계정별 권한·2단계 인증 또는 관리자 경로의 별도 접근 통제. 현재 단일 토큰 방식이다.
- 로그인·업로드·공개 이벤트 API 요청량 제한 및 비정상 요청 경보.
- 의존성 취약점 검사·운영 비밀값 강도·Render/GitHub 계정의 2단계 인증 확인.
- 보상 DB와 영수증 업로드의 운영 재시작 보존 검사.

게스트 기기 ID는 재연결 수단이므로 비공개로 취급한다. 이번 변경은 보상·지급을 켜거나 운영 비밀값을 교체하지 않는다.
