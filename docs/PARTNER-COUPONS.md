# 제휴 쿠폰 기반 · 로컬 개발

2026-10-19. 실제 제휴·발급·운영 배포는 하지 않았다.

- MY의 내 쿠폰은 로그인된 본인 쿠폰만 조회한다. 계약 근거는 고객 응답에서 제외한다.
- 쿠폰은 포인트 차감 없는 가게 혜택이다. 포인트를 현금처럼 매장에서 결제하는 기능이 아니다.
- `PARTNER_COUPONS=on`과 영구 저장 조건을 충족해야 관리자 발급·사용·취소 API가 열린다. 로컬 테스트만 `RECEIPT_REWARDS_ALLOW_VOLATILE=on`을 사용한다.
- 모든 변경은 기존 관리자 인증·2FA 정책을 통과해야 한다. 점주에게 관리자 토큰을 배포하지 않는다.
- 발급 필수: 고객 uid, 지점 ID·이름, 혜택, 이용 조건, 계약 참조, 만료일, 고유 요청 ID.
- 발급 재시도는 같은 요청 ID와 같은 내용이면 동일 쿠폰을 반환한다. 다른 내용은 충돌로 거절한다.
- 사용·취소는 issued 상태에서만 허용한다. 다른 지점, 만료, 사용 완료, 취소 상태는 거절한다.
- SQLite 즉시 트랜잭션과 감사 기록으로 동시 중복 사용을 차단한다. 테이블은 기존 보상 DB 안에 저장된다.
- 운영 OFF에서도 이미 발급된 쿠폰은 조회한다. OFF는 변경 작업을 막으며 조회 내역을 삭제하지 않는다.

## 아직 남은 운영 준비

실제 계약, 고객 연락/문의 경로, 점주 계정 온보딩·키 전달/회수 절차, 실제 백업 복원 및 실기기 검수.
관리자 발급 UI(`/static/admin-coupons.html`)와 점주 확인 UI(`/static/merchant-coupons.html`)를 로컬 구현했다. 고객 화면 캡처·고정 쿠폰 ID만으로 사용 처리하지 않는다.
무제한 자동 발급·실제 브랜드 쿠폰 구매·Npay 전환·계좌 송금을 실행하지 않는다.

## 검증

`python -B -m scripts.check-coupons`: 운영 OFF, 무인증, 다른 uid, 요청 멱등성, 다른 지점, 8개 동시 요청 중 정확히 1개 사용, 취소·만료, 새 저장소 인스턴스에서 기록 유지, 포인트 무차감.
재시작 검증은 로컬 저장소 재생성 기준이며 Render 재시작 생존 검증은 아니다.

## 점주 사용 코드

- 고객 MY에서 본인 쿠폰에 한해 2분짜리 16자리 난수 코드를 발급한다. DB에는 SHA-256 해시만 저장하며 재발급은 이전 코드를 무효화한다.
- `PARTNER_MERCHANT_KEYS`는 서버 환경의 JSON 지점 ID→32자 이상 가게 전용 키 매핑이다. 실제 운영값은 이 문서·레포·브라우저 저장소에 넣지 않는다. 키 회전은 서버 환경에서 해당 값을 교체해 진행하며, 점주에게 관리자 토큰을 전달하지 않는다.
- 점주 키는 지점 하나에 한정한다. 확인→혜택 제공·사용 완료의 두 단계이며, 서버는 사용 순간에도 지점·코드·만료·쿠폰 상태를 다시 확인한다.
- 고객 UID·계약 참조는 점주에게 내려주지 않는다. 점주는 포인트·영수증·송금·취소·발급 권한이 없다.
- API 키 방식의 초기 도구이며 점주별 다중 사용자·2FA·자동 가입·분실 복구는 아직 구현하지 않았다. 운영 사용 전 별도 검수가 필요하다.
- 점주 API는 IP당 분당 20회·전체 120회로 제한한다. 쿠폰 코드 발급은 기존 고객 인증과 보상 요청 제한을 적용한다.
