## 0. 북극성 (이게 전부다)

**목표는 완벽한 앱이 아니라, 서비스 런칭 + 유저 확보다.**

| 단계 | 성공 정의 |
|------|-----------|
| Launch | 스토어/웹에서 실제 유저가 스와이프 → 길안내/배민까지 감 |
| **성공 라인** | **DAU 1,000** (하루에 천 명만 들어와도 성공) |
| 그 전 | 허브 1곳부터 열어 제품 루프·공유가 도는지 검증 |

완벽주의 금지. GNN·숏폼·혼잡도·전국 동시 오픈은 **1,000 DAU 이후에만**.  
지금 할 일 = **런칭 가능한 얇은 제품 + 유입 파이프**.

### 1,000 DAU까지 우선순위

1. **설치 → 첫 Let’s Go** 가 되게 (온보딩·위치·스와이프·딥링크)
2. **송도 근처 재고**가 비지 않게 (Visit-ready)
3. **공유·Duo**로 오가닉 유입
4. 점심 타임 푸시/커뮤니티 시드 (카톡방·오피스)

품질 기준: “부끄럽지 않은 베타”면 출시. 버그 zero가 목표가 아님.

## 3. 핵심 기능 (통합)

### 3.1 초정밀 온보딩
1. 카카오 / 구글 로그인  
2. 위치 팝업 1장  
3. 음식 사진 밸런스 **스와이프 3장만** → 초기 취향 벡터  
4. 알레르기·예산 등 **텍스트 설문 없음** — 3장 + 이후 스와이프에서 *추정* (명시 입력이 아님)

### 3.2 원스크린 스와이프
- 상단: **방문 / 배달** 토글만  
- 카드: 사진 ≥80% + 상단 브랜드 카피 + 상호·거리·#태그1  
- Right(수락) → 폭죽 → **즉시 딥링크** (중간 확인 화면 없음)  
- Left(거절) → 다음 카드 + 실시간 재학습  
- Long-press → 영업·평점·짧은 리뷰  
- 연속 Nope 5 → 골드 정답 카드  
- 앱 오픈마다 **현재 GPS**로 큐 재구성, Perfect 슬롯 **5**

### 3.3 스마트 반경 (모드 × 날씨 × 메뉴 민감도)

| 모드 | 기본 반경 | 축약 조건 | Let’s Go 랜딩 |
|------|-----------|-----------|----------------|
| **방문** | **500–700m** (도보) | 악천후 시 하한(≈500m) 쪽 | **네이버 지도** 길안내 URL |
| **배달** | **1.0–1.5km** | 비/눈 **또는** 배달 민감도 높음 → **≤1km 강제** | **배달의민족** 검색 딥링크 |

- “근처에만” 원칙은 유지. 허브/동 전체로 반경을 키우지 않음.  
- 반경은 세션·카드 단위로 엔진이 산출 (`effective_radius_m`).

### 3.4 Growth (유지)
식탐 영수증 공유 · Duo 3+3 교집합 1곳.

## 4. 메뉴 민감도 · 동적 반경 엔진

### 4.1 메뉴 속성 (등록 시 부여)

식당/메뉴 시드·어드민 등록 시 배달 품질 민감도 점수 (0–1, 높을수록 멀면 맛 붕괴):

| 필드 | 의미 | 높은 예 |
|------|------|---------|
| `temp_hold` | 온도 유지력 (낮을수록 민감) | 뚝배기 국물 → 민감↑ |
| `texture_hold` | 식감 보존력 | 바삭 돈가스 → 민감↑ |
| `spill_risk` | 국물/포장 위험 | 라면·찌개 |
| `delivery_sensitivity` | 위 가중합 또는 모델 출력 **종합 민감도** | 0.8+ = 최고 민감 |

방문 모드에서는 민감도가 반경보다 **랭킹 보너스/페널티**에만 약하게 쓰이거나 무시 가능.  
배달 모드에서는 **반경 상한 산출에 직접 사용**.

### 4.2 실시간 환경 필터

앱/세션 시작 시:
1. GPS  
2. 날씨 API → `weather_flag` (`clear` \| `rain` \| `snow` \| `hot` \| `cold` …)  
3. 유저 토글 `intent`: `visit` \| `delivery`

### 4.3 반경 산출 (의사코드)

```
if intent == visit:
  base = 700
  if weather in (rain, snow): base = 500
  effective = clamp(base, 500, 700)

if intent == delivery:
  base = 1500  # 맑음 상한
  if weather in (rain, snow): base = min(base, 1000)
  # 카드/메뉴별: 민감도 높으면 더 축소
  # radius_i = base * (1 - 0.4 * delivery_sensitivity_i)  등
  # 하드 캡: sensitivity >= 0.8 → radius_i <= 1000
  effective_i = clamp(radius_i, 800, base)  # 하한은 제품안 조정 가능
```

피드 쿼리: `ST_DWithin(place, user, effective_radius_m)`  
민감도별 카드마다 반경이 다르면: **후보 풀은 세션 max 반경으로 가져오고**, 카드 노출 직전 메뉴 반경으로 컷 — 또는 풀을 보수적으로 min 반경으로.  
CTO 기본: **세션 풀 = 해당 intent의 상한 반경**, 노출 시 `distance_m <= radius_for(menu, weather)`.

## 5. 하이브리드 API 파이프라인

```
[실시간]
GPS + Weather + intent(visit|delivery)
        ↓
반경 엔진 → effective radius
        ↓
① 카카오 로컬 API  — 반경 내 기초 POI (장소·좌표·카테고리)
        ↓ 비동기
② 네이버 검색 API — 고화질 이미지·최신 리뷰 덧입히기
        ↓
자체 DB(places/menus/sensitivity) 머지 · 랭킹 · /feed 카드
        ↓
Let’s Go → 네이버지도(방문) | 배민(배달) 딥링크
```

- ① 없으면 카드 스킵. ② 지연 시 플레이스홀더/캐시 이미지 후 교체.  
- 시드 허브 재고와 카카오 결과를 **교집합 또는 enrichment** (오픈 market 우선).  
- 호출 쿼터·캐시(장소 TTL) 필수.

## 8. 추천 규칙 (요약)

1. intent + weather + sensitivity → **effective radius**  
2. 반경 ∩ 영업중(방문) / 배달가능 힌트(배달)  
3. 취향 벡터 + nope 페널티 + (배달 시) 민감도·거리 트레이드오프  
4. 연속 nope 5 → 골드(현 반경 안 1위)  
5. Perfect 5 = 앱 오픈 세션·**그 좌표** 기준
