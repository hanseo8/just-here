# 영수증 접수·검토·지급 상태 검증 (2026-11-07)

상태: 로컬 코드 수정 및 격리 자동 테스트 통과. 운영 배포·실기기 검수·실제 송금은 하지 않음.

## 수정
- 업로드: 사진/일시 검증, 진행 안내와 aria-busy, 중복 클릭 차단, 45초 연결 제한. 결과 불명확 시 입력을 유지하고 내역 확인을 안내하며 자동 재전송하지 않음.
- 업로드 폼이 숨겨져도 상단 업로드 안내 영역에서 접수 상태를 확인할 수 있음.
- 영수증 승인/반려의 동일 결정 재시도는 중복 적립 없이 반환. 확정된 결정에 반대 요청은 409로 거절.
- MY 기본 영수증 조회 30→100건으로 14일 최대 42건을 모두 표시. 전체 무제한 이력/페이지 구분은 별도 범위.
- 영수증별 검토/적립과 지급 접수/처리/완료/반려를 구분. 적립만으로 송금 완료를 표시하지 않음.
- MY 데이터 새로 로드 시 지급 대상·내역도 갱신. 지급 중 중복 제출 차단, 반려 사유와 포인트 반환 표시.

## 검증
- python -m scripts.check-receipt-settlement-flow: 인증된 게스트의 베타 선정·실제 multipart 업로드, 중복 사진/식사 차단, 비공개 사진 접근, 부정적 후기 승인, 300P 단일 적립, 상태 충돌, 지급 보류/반려/반환/재신청/완료, 계좌 원문 삭제, 장부 대조, SQLite 재기동 보존.
- python -m scripts.check-rewards-api: 사용자/관리자 인증·2차 인증, 본인 사진, 백업/복구·유지보수.
- python -m scripts.check-payouts: 동시 지급 신청 단일 예약, 100/300원 이전 데이터 유지, 중복 송금 참조 차단, 반환과 암호화·재시작.
- python -m scripts.check-beta-campaign: 15명/264,000원 한도, 14일/하루3건/42건, 42건 MY 조회, 참여비 5,000원 조건.
- python -m scripts.check-reward-identity: 미인증 보상 차단·동일인 계정 복구·개인정보 원문 미보관.
- node scripts/check-receipt-flow-ui.cjs: 입력 검증·중복 클릭·전송 실패/시간 초과·계정 전환·검토/지급 문구 구분.
- node scripts/check-payout-flow-ui.cjs: 승인 후 대상 갱신·중복 제출·대기/반려/완료 표시.
- node scripts/check-my-ui.cjs, node scripts/check-rewards-web-auth.cjs: MY 동작·마크업, 인증 재조회 시 변이 재전송 없음.
- npm run bundle --prefix mobile, npm run check --prefix mobile: 고객용 정적 묶음·경로·네이티브 브리지 검사. APK/AAB 빌드나 실기기 검수 증거가 아님.

## 운영 전
- 이전 단계의 본인인증 복귀 변경 및 이번 변경은 아직 배포하지 않음.
- 포트원 실제 LIVE 인증, 모바일 사진 선택/네트워크 단절, 관리자 은행 거래 증빙 확인은 별도 실운영 검수가 필요.
- 테스트 paid 상태는 가상 참조로 관리자 기록 전이만 검증. 은행 송금 실행 또는 입금 확인을 의미하지 않음.
