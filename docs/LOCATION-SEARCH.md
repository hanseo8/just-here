# 위치 직접 선택 — 로컬 개발

첫 진입 시 위치를 자동 확인한다. 정상 화면은 자동 위치·날씨와 '근처 메뉴 고르기'를 중심으로 한다. 아래에는 작은 보조 안내 '위치가 안 잡히나요? 동네·역·주소로 검색'을 항상 표시하고 입력란은 접어 둔다.
위치 권한 거부·오류·시간 초과 시에만 직접 선택 입력을 펼친다. 송도로 임의 이동하지 않는다. GPS 재확인은 별도 버튼으로 제공한다.
자동 확인 중 시작 버튼을 눌러도 진행 중 요청을 공유하여 권한을 중복 요청하지 않는다. OAuth 복귀 시 복원한 위치가 늦은 자동 응답에 덮어쓰이지 않도록 한다.
동네·역·주소 검색 결과를 사용자가 선택하면 해당 좌표를 추천과 날씨 조회에 사용한다. 늦은 GPS 응답이나 이전 날씨 응답은 선택한 위치를 덮어쓸 수 없다.
검색어와 주소·좌표는 신규 분석 이벤트에 넣지 않는다. 검색 요청은 POST 본문으로 전달하며 응답은 no-store. 검색어의 카카오 API 전달 안내를 UI에 표시한다.
서버 키만 사용하며 카카오 공식 주소/키워드 API에 최대 두 번 요청한다. 클라이언트에 키를 노출하지 않는다. 빈 결과·오류·검색 중 상태와 입력 길이·제어문자 검증, 요청 제한을 포함한다.
공식 문서: https://developers.kakao.com/docs/ko/local/dev-guide

검증: check-location-search.py(가짜 upstream 응답/임시 데이터), check-location-ui.cjs(GPS 거부/시간 초과/지연 콜백/직접 선택), 로컬 모바일 화면.
로컬 화면의 강남역 및 날씨는 검증용 예시 데이터이며 실시간 날씨 검증을 의미하지 않는다.
운영 서버의 기존 키로 공개 장소명 '강남역'을 일회성 조회해 실제 카카오 응답 5건, 역명 포함 및 좌표 유효성을 확인했다. 서버 파일·환경 설정·고객 데이터는 변경하지 않았다. 전체 지역 검색 품질을 보장하는 검사는 아니다.
모바일 390px·320px 화면, 빈 결과 안내 및 재검색, 직접 선택 후 음식 선택·거리 단계 이동을 확인했다. 거리 시각화에도 선택한 지역명이 표시된다.
자동 우선 수정 후 390px 모바일에서 성공 시 보조 검색 안내·한 번 눌러 메뉴 이동, 거부 시 직접 선택 입력 자동 표시를 확인했다. 보조 안내를 눌러 입력란을 펼치고 접는 동작도 확인했다. GPS 응답이 도착해도 사용자가 이미 펼친 입력란을 닫지 않는다. 이 화면 검증에는 로컬 서버에서 주입한 가짜 GPS 성공/거부 응답을 사용했으며 사용자의 실제 위치나 브라우저 위치 권한은 사용하지 않았다.
영구 저장·새 앱 패키지 생성·2번 운영 배포는 아직 하지 않았다.
