# 300P 영수증 보상 개발·검증 순서

## 원칙

- 첫 파일럿은 현금 300원이 아니라 앱 안의 `300P` 적립으로 운영한다.
- 포인트의 사용처와 환급 조건을 공개하기 전에는 현금처럼 표현하지 않는다.
- 추천을 통해 선택한 방문 매장만 대상이다. 배달과 임의 매장 영수증은 받지 않는다.
- 영구 저장소가 없으면 기능을 열지 않는다. 포인트 원장 유실 가능성이 있는 상태에서 보상을 약속하지 않는다.
- 보상 후기임을 화면과 향후 공개 후기에서 명확히 표시한다.

## 0단계 — 운영 기반

배포 전 필수 조건이다.

1. Render 영구 디스크를 `/data`에 연결하고 `DATA_DIR=/data`를 적용한다.
2. 재시작 전후 `rewards.sqlite3`, 영수증 파일, 사용자와 이벤트 파일이 같은지 비교한다.
3. `ADMIN_TOKEN`과 `GUEST_SIGNING_SECRET`을 운영 비밀값으로 설정한다.
4. 관리자만 원본 영수증을 볼 수 있는지 확인한다.
5. 개인정보 처리방침에 수집 항목, 목적, 보관 기간, 삭제 방법을 추가한다.

이 단계 전에는 `RECEIPT_REWARDS=off`를 유지한다.

## 1단계 — 폐쇄형 300P 파일럿

현재 구현 범위다.

- 추천 선택과 매장·메뉴·사용자를 하나의 귀속 ID로 묶는다.
- 최근 3일 이내 영수증만 접수한다.
- 하루 1건, 동일 이미지, 동일 승인번호, 동일 추천의 중복 접수를 막는다.
- 운영자가 영수증을 보고 승인하거나 사유와 함께 반려한다.
- 승인 원장은 수정형 잔액 대신 추가 기록으로 남긴다.
- 사용자는 `/rewards`에서 검토 중 포인트와 적립 잔액을 확인한다.

파일럿 규모는 30일 또는 승인 영수증 100건 중 먼저 도달하는 시점까지로 제한한다.

## 2단계 — 지급과 부정 사용 운영

1단계 지표가 통과한 뒤 개발한다.

- 포인트 사용처 또는 교환 수단을 확정한다.
- 사용자 본인 확인, 지급 실패, 취소와 회수 원장을 추가한다.
- 같은 카드·상호·금액·시각 조합, 편집 이미지, 반복 기기 패턴을 위험 신호로 표시한다.
- 원본 영수증 자동 삭제와 감사용 최소 정보 보존 작업을 배치로 실행한다.
- 관리자 권한을 단일 토큰에서 계정·역할 기반으로 바꾼다.

## 3단계 — 유입 실험

- 광고 문구는 “식당 추천을 받고 실제로 먹은 뒤 영수증 인증 시 300P”로 통일한다.
- 광고별 유입, 추천 시작, 매장 선택, 지도 이동, 영수증 접수, 승인까지 같은 캠페인 ID로 측정한다.
- 첫 실험은 지역을 제한하지 않되 예산과 일일 승인 건수에 상한을 둔다.
- 보상만 받고 떠나는 사용자를 구분하기 위해 7일 내 재방문과 두 번째 추천 선택을 본다.

통과 기준:

- 추천 시작 대비 매장 선택률 35% 이상
- 매장 선택 대비 지도·주문 이동률 50% 이상
- 이동 대비 승인 영수증률 15% 이상
- 승인 사용자 7일 재방문율 20% 이상
- 승인 1건당 총비용이 향후 매장 과금 예상액보다 낮음

## 4단계 — 가게 광고 상품

사용자 행동이 충분히 쌓인 뒤 시작한다.

- 노출 판매가 아니라 검증된 방문 또는 승인 영수증 기준으로 과금한다.
- 광고 매장은 일반 추천과 구분하고 추천 적합도 필터를 그대로 통과해야 한다.
- 매장 대시보드에는 노출, 지도 이동, 승인 방문, 재방문 의향만 제공한다.
- 최소 표본 이하의 매장 데이터는 개인을 추정할 수 없도록 숨긴다.

## 중단 기준

- 부정 접수율이 10%를 넘음
- 승인 1건 처리 시간이 3분을 넘음
- 7일 재방문율이 10% 미만
- 저장·원장 불일치가 한 건이라도 발생
- 보상 비용을 제외한 사용 가치가 인터뷰와 행동에서 확인되지 않음
