# Android·iOS 배포 준비

2026-10-19 · 스토어 양쪽 배포 요청. 현재 서명 앱·스토어 제출 완료 아님.

## 이번 공통 수정
- 서비스워커는 공개 셸·정적 리소스만 캐시. MY·관리자·점주·미리보기·API·인증 헤더 요청은 제외.
- no-store/private·실패 응답은 캐시하지 않으며 정적 파일 실패에 홈 HTML을 반환하지 않음.
- Docker 빌드 컨텍스트에서 로컬 사용자 데이터·영수증·백업·DB·환경 비밀키를 제외하고 승인 메뉴 원본만 포함.
- 설치용 manifest 색상과 앱 ID 정리. 이는 네이티브 배포 완료를 의미하지 않음.

## 네이티브 구현 방향
기존 화면을 재사용하는 Capacitor 기반을 우선 후보로 한다. 단순 운영 URL 원격 로딩만으로 출시하지 않는다.
네이티브 패키지에 고객 화면을 번들하고 관리자·점주 도구는 웹 운영 도구로 분리한다.
앱용 API 주소·인증·CORS·외부 링크·OAuth 콜백을 먼저 정리해야 한다. 웹 기준 상대 경로를 그대로 복사하면 앱에서 동작하지 않는다.
앱 식별자·팀 ID·서명 인증서·카카오 앱 키의 플랫폼 등록은 실제 소유 계정과 맞춘 뒤 확정한다.

## 제출 전 필수 개발
1. 네이티브 위치 권한 거절·재시도와 영수증 카메라/사진 선택·파일 변환·용량 제한.
2. Android 뒤로 가기, iOS 안전 영역, 키보드·스크롤·외부 지도·전화 링크.
3. 카카오 계정 연결·복귀·앱 재설치 후 복구. Apple 로그인 심사 적용 여부 확인 및 필요 기능 구현.
4. 앱 내 계정/관련 데이터 삭제 흐름과 외부 삭제 요청 웹 페이지. 보존 필요 데이터의 범위와 기간은 실제 정책 확정 후 구현.
5. 현재 영수증·지급·쿠폰 수집 항목을 반영한 개인정보 처리방침, 실제 문의처, 스토어 개인정보 공개·Google Data safety.
6. 실제 데이터 포함 백업/복구·재시작 보존, 지급 결과 불명확 상태의 대사·고객 문의.
7. Android 내부 테스트·iOS TestFlight 실제 기기 검수 후 AAB/IPA 서명 빌드 및 심사 자료 준비.

## 사용자 소유 계정/환경 필요
Google Play Console, Apple Developer/App Store Connect 등록 여부·실제 법적 게시자명 확인.
iOS 네이티브 빌드에는 macOS와 Xcode 또는 사용자가 승인한 해당 빌드 환경 필요. 현재 Windows에서는 iOS 서명·실기기 배포 검증 완료로 표시하지 않는다.
계정 비용 지출·스토어 등록·정책 확정·실제 보상 운영 활성화는 아직 진행하지 않았다.

## 현재 출시 보류 사유
네이티브 프로젝트와 위치·사진 권한 브리지는 mobile/에 구현했다. 앱 인증 복귀·실제 계정 삭제 엔진·실기기 검수는 미완료다.
현 UI·백엔드 회귀 통과만으로 스토어 승인이나 오류 없음을 보장하지 않는다.

## 2026-10-19 추가: 삭제 요청 접수
사용자는 Mac 사용 불가, Google Play 개발자 계정 미등록으로 답했다. 앱스토어 양쪽 목표는 유지한다.
MY에서 `/account/delete`로 이동해 인증된 본인 계정의 삭제 검토 요청을 제출하고 요청 상태를 조회할 수 있다.
관리자는 `/static/admin-account-deletions.html`에서 기존 관리자 인증·2FA 정책으로 요청을 보고 검토 시작만 처리한다.
요청은 기존 보상 SQLite 안에 보존하며 동시·반복 요청은 계정당 한 건이다. 영구 저장이 확인되지 않으면 제출을 거절한다.
포인트·지급·영수증·외부 인증·로그에 대한 실제 삭제와 보존 규칙은 아직 실행하지 않는다. 이 접수 기능만으로 Apple/Google 삭제 요건을 충족했다고 판단하지 않는다.
신원 복구가 안 되는 다른 브라우저용 요청과 처리 결과 통지·문의 채널 역시 후속 과제다.
검증: `python -B -m scripts.check-account-deletion` · 본인/관리자 권한, 명시적 동의, 영구 저장 조건, 요청 제한, 동시 중복 차단, 로컬 재시작 유지.

### 삭제 전 검사·철회 추가
관리자는 요청별 영수증 검토·지급 대기/처리·잔액·활성 쿠폰을 읽기 전용 스냅샷으로 확인한다. 이 검사는 실행 권한이 아니며 `can_execute=false`를 유지한다.
고객은 요청/검토 상태에서 철회하고 다시 요청할 수 있다. 철회된 요청을 관리자가 검토 상태로 되돌리지 못한다. 지급·잔액·영수증은 변경하지 않는다.
사용자 JSON·이벤트·SQLite·이미지·외부 인증·백업의 삭제와 보존 규칙을 확정하지 않았으므로 실제 삭제 엔진 및 삭제 후 토큰 차단은 여전히 미구현이다.
